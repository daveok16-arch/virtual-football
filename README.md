# Virtual Football Prediction Bot

Captures live Scheduled Virtual Football data from SportyBet (GoldenRace provider)
via Chrome DevTools Protocol WebSocket interception, runs a confidence-based
prediction model, and sends predictions to Telegram. Deployable to Render.

## What it does

1. **Capture** — Launches headless Chromium, navigates to SportyBet, attaches to
   the GoldenRace (`virtustec`) iframe's CDP sub-session, and intercepts the
   WebSocket frames carrying football fixtures, 1X2 odds, league standings, and
   resolved results.
2. **Predict** — De-viggs the published 1X2 odds into fair probabilities; the
   prediction is the highest-probability outcome and the confidence *is* that
   probability (P(prediction correct)). League standings are used as a secondary
   sanity check (AGREE/DISAGREE with the odds favorite).
3. **Notify** — Sends an HTML report of the top HIGH/MEDIUM-confidence picks to a
   Telegram chat, on a recurring interval.

## Why this model

Virtual football outcomes are RNG-generated by GoldenRace, and the odds are set
by the same engine. So the de-vigged odds-implied probability is the best
available estimate — no external signal beats it. The bot is honest about this:
it reports the house vig (~8.5%) and notes that the vig cannot be beaten
long-term. Its value is surfacing the genuinely reliable (HIGH-confidence) picks
and flagging where standings disagree with the odds.

Backtested on 57 resolved matches: the HIGH tier (≥55% confidence) is
well-calibrated (predicted 61% → actual 62.5%); MEDIUM/LOW tiers over-predict.

## Files

| File | Purpose |
|------|---------|
| `intercept-scheduled-virtuals.js` | Manual CDP interception CLI (perpetual listener, logs NDJSON) |
| `capture.js` | Reusable capture function (importable, bounded window) |
| `virtual-football-model.js` | Prediction engine: de-vig odds, standings corroboration, confidence |
| `predict.js` | CLI: `predict` (live predictions + overhead) / `backtest` (calibration) |
| `format-predictions.js` | Builds prediction list + Telegram HTML report |
| `telegram-notify.js` | Sends messages to Telegram (Bot API, zero-dep) |
| `server.js` | Health-check HTTP server for Render |
| `bot-runner.js` | Orchestrator: capture → predict → notify loop (the deployed entry point) |
| `Dockerfile` | Renders the service with Chromium + puppeteer |
| `render.yaml` | Render service definition |
| `.env.example` | Documents required env vars (copy to `.env`) |
| `league-mappings.json` | playlistId → league name |

## Local usage

```bash
npm install

# One-off: capture + print predictions + slate analysis
node intercept-scheduled-virtuals.js   # Ctrl+C after a few minutes
node predict.js
node predict.js backtest               # calibration on resolved matches

# Bot loop (capture → predict → Telegram every 5 min)
cp .env.example .env                   # fill in TELEGRAM_BOT_TOKEN + TELEGRAM_CHAT_ID
node bot-runner.js
```

If `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` are unset, the bot still runs and
prints reports to stdout (handy for local testing).

## Deploy to Render

1. Push this repo to GitHub.
2. In Render: **New → Web Service** → connect the repo. Render detects
   `render.yaml` automatically (or pick the Dockerfile runtime).
3. Add environment variables in the Render dashboard (secret — never committed):
   - `TELEGRAM_BOT_TOKEN` — from [@BotFather](https://t.me/BotFather)
   - `TELEGRAM_CHAT_ID` — your chat/channel id
   - `RUN_INTERVAL_SECONDS` (default 300), `CAPTURE_SECONDS` (default 90)
4. Deploy. The health check hits `/` (returns `OK`); `/status` shows run history.

The Dockerfile installs system Chromium and sets `PUPPETEER_EXECUTABLE_PATH`, so
puppeteer runs headless inside the container.

## Environment variables

| Var | Required | Default | Description |
|-----|----------|---------|-------------|
| `TELEGRAM_BOT_TOKEN` | for notifications | — | Bot token from @BotFather |
| `TELEGRAM_CHAT_ID` | for notifications | — | Target chat/channel id |
| `RUN_INTERVAL_SECONDS` | no | 300 | Seconds between capture/predict/notify cycles |
| `CAPTURE_SECONDS` | no | 90 | Seconds to listen per capture window |
| `PUPPETEER_EXECUTABLE_PATH` | no | bundled | Chromium path (set to `/usr/bin/chromium` in Docker) |
| `PORT` | no | 10000 | Health server port (Render sets this) |

## Responsible note

Virtual sports are house-edged RNG games. This tool quantifies the slate and
reports calibrated confidence; it cannot overcome the built-in vig long-term.
